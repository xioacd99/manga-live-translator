# 方法、限制与公平比较边界

## 同一批图片，而不是挑出更容易的样本

复用 EN01—EN10 的历史英文漫画、公版来源与冻结标注。10图共67个确定的文字区域、4个不确定区域；OCR主指标的参考分母为2215个字符、522个空白分词。6张仅局部标注，4张全标注。这不是现代英译日漫/韩漫代表性数据集，也不是总体准确率估计。

GT SHA256：`984017f90ce822edb0c480207ed29ec8ec5ded587ba37f7ec40b3eb35e22753f`。所有模型读取相同原图 SHA，不读取GT来选参数；完整原图、GT及模型转写不随报告发布。[来源与图片哈希](../english-japanese-2026-11-03/english/sources.json)。

## 指标不是“识别正确率=100%-CER”的简单排名

- 主CER：Unicode NFKC标准化、去所有空白，保留大小写和标点；字符替换S、删除D、插入I之和除以参考字符数N。CER可以超过100%。
- 去标点CER：额外去Unicode P类标点，是辅助诊断，不替换主指标。
- WER：NFKC后按空白分词，保留大小写/标点。
- 匹配只用几何：预测框至少50%面积落入一个GT框，且只归属一次，再使用固定`line-column-overlap-v2`几何顺序；不根据预测文字寻找最像的参考答案。
- 某参考区域没有任何有效文字输出时计完整字符删除，不从分母删掉难样本。字符删除也可能来自识别漏字，不能全部叫检测漏检。
- 生成式Spotting的最终框和DB原始行框不是同一输出粒度。没有独立检测阶段不等于检测召回为0；报告只比较共同的定位＋文字成绩，另给空输出区域数。部分标注不能估计全页误检率。
- 同一GT段落被错误合并为大框，可能过不了50%归属规则，整段计删。因此CER包括定位/分组错误，不是给定正确裁图后的纯识字能力。

## 分辨率四档：只有一个预先声明的空间变量

固定v6 small权重、RapidOCR/ORT版本、归一化、DB阈值、方向分类器、识别器以及CPU1线程。短边目标为1024、1536、2048、2560，统一长边上限4096。原图宽高为w、h时：

`ratio = min(target_short / min(h,w), 4096 / max(h,w))`

每个尺寸四舍五入后用INTER_LINEAR缩放；检测器保持max4096，并按库规则取整到32倍数。**超长条受长边上限约束，实际短边可能不到目标，多个档可能变为相同实际尺寸。** 不是强行拉伸成正方形。识别裁图来自缩放后的图，因此这是整条OCR流水线的空间预处理对照，不是只改检测器分辨率。

每档独立进程，同10图每图连续3遍，首遍和后两遍均单独记录。主时延采用后两遍均值，模型初始化独立记录。进程累计峰值RSS不是每张图独立峰值。实际tensor shape的轻量观察计入wall，RSS读取在计时外，各档记录方式相同。固定1024→1536→2048→2560顺序，没有随机交错，因此宿主机时段差异仍是限制。共享排他锁避免其他OCR实验并行争抢CPU。

此前2048单遍pilot只证明可行性，不替代本轮四档×10图×3遍正式结果。

## VL1.6：全页Spotting，不先拿GT框喂模型

官方GGUF固定revision/哈希，llama.cpp CPU4线程，无GPU、无付费API、无外部图片服务。只发送本地图片data URI至127.0.0.1；不启用广域监听或工具执行。模型下载和图片推理是不同网络边界。

任务固定`Spotting:`，温度0、seed0、8192上下文、4096输出token；保留special tokens。宽高均小于1500时按官方建议Lanczos放大2倍，其余保留输入尺寸，视觉模型继续应用固定最小112896/最大1605632像素预算。该内部像素预算与v6的目标短边不是同一参数，不能称两模型看到了同样的有效分辨率。

每段8个LOC值对应4个角点，除以1000后映射到原图宽高。严格拒绝缺失/越界坐标、零面积包围框、未解析尾部；非正常stop或解析失败整页按无有效结果评分，并保存原始输出。没有按图片加大预算或人工改写模型文字。预算/格式失败率单列；由整页拒绝引起的删除只说明这套固定预算整页服务没有成功交付，不能推导模型在正确裁图上的纯识字上限。若报告完整前缀数量或重复片段，仅为非评分诊断，不替换原始失败预测。

单次有序遍历10图，模型已加载后的不同页面请求不等于同图重复暖调用。请求时间不包含此前PIL解码、放大和PNG编码；初始化独立记录。VL是CPU4，而v6是CPU1，不能从本报告得出同资源加速比或Mac M4速度。

## 本地部署的结论边界

Python/原生CPU结果不是Chrome扩展已集成，更不是Mac M4测量。官方Apple Silicon说明支持研究本机原生/MLX路线；若使用本地服务，需要单独处理安装、权限、来源限制、localhost认证/请求预算、下载完整性、取消与内存回收。当前产品默认模型未修改。
