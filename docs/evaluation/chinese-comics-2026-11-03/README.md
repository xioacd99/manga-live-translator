# 中文漫画五方案实测对比

日期：2026-11-03。状态：供方案选择的云端 CPU 实验，**没有切换产品默认方案、没有合并 main 或发布**。

## 先看结论

在这批《斗破苍穹》5张、《斗罗大陆》5张的中文漫画配图上，**A：PP-OCRv5 mobile 的完整检测+识别流程最值得优先验证浏览器集成**。它同时取得最低字符错误率和最快整图处理时间。此结论只适用于固定10图及本次参数，最终方案仍由维护者选择。

关键发现不是“RT-DETR检测差”：其段落框与参考框在 IoU≥0.5 下匹配44/45，唯一未匹配目标是DP03下缘已截断对白。更大的问题是识别器能力，以及段落框接到单行识别器时的接口不匹配。不能把检测、OCR、翻译质量混为一谈。

### 主结果

CER越低越好，允许超过100%；“完全正确块”要求整块标准化后逐字一致，包括标点。所有方案使用同一44块确定参考文字，共536字符；去标点分母387字符。**不是模型confidence，也不是翻译准确率。**

|方案|主CER（含标点）|去标点CER|完全正确块|暖处理秒/图|计时口径|
|---|---:|---:|---:|---:|---|
|A · PP-OCRv5完整流程|16.23%|3.36%|29/44|0.470|整图真实wall time|
|B · Tesseract中文整图|103.17%|107.75%|1/44|0.542|整图真实wall time|
|C · RT-DETR + Tesseract裁剪|58.58%|57.62%|2/44|1.118|分阶段实测耗时相加，不是流水线wall time|
|D · RT-DETR + Paddle直接识别|71.64%|67.96%|13/44|0.831|分阶段实测耗时相加，不是流水线wall time|
|E · RT-DETR裁剪 + Paddle再次检测识别|62.87%|53.75%|3/44|3.081|分阶段实测耗时相加，不是流水线wall time|

A的含标点与去标点结果差距较大，主要涉及省略号等标点遗漏。参考省略号经NFKC会展开成点，必须同时看两列，不能只选对某方案有利的一列。去标点CER不是纯汉字CER，仍保留非标点符号、数字和字母。中文没有天然空格词界，本轮未选择中文分词器，因此不报告容易误导的WER。

## 五种实际配置

- **A**：RapidOCR 3.4.5 + ONNX Runtime CPU 1.23.2，PP-OCRv5 mobile DB检测器 + mobile多语言识别器 + 0/180°分类器。不是Paddle原生运行时，也不是server模型。默认DB `limit_side_len=736, limit_type=min`，全局最长边上限2000。活跃权重22,036,414字节。
- **B**：native libtesseract 5.5.0 持久C API，官方tessdata_best `chi_sim`，自动依赖 `chi_sim_vert`，总26,154,930字节。整图PSM11，仅全文为空时一次PSM3；不使用当前扩展仅英语的字库。
- **C**：现有RT-DETR v4-s int8，阈值0.3，真实产品框解码/选择，Pillow预处理；文字框每边补4原像素、2倍bicubic放大，Tesseract中文PSM6。无框时整图2倍PSM6。与B比较包含检测、裁剪、放大及PSM多项变化，不能把增益单独归因于检测器。
- **D**：同一RT-DETR最终段落框，直接裁剪后进入Paddle同一识别器，不再检测、不额外放大。识别器主要面向单行，直接接多行段落是明确的粒度不匹配对照，失败不能概括为Paddle识别能力差。
- **E**：同一RT-DETR框裁剪后，再运行Paddle完整DB+分类+识别。它确实二次检测，不是rec-only；本次默认裁剪/缩放参数下DP03与DL01输出为空，且小裁剪上重复DB带来成本。已查实DP03候选被识别0.5分数阈值滤除；DL01部分候选低分被滤除、另一竖裁剪DB零框。默认最短边736会显著放大小图，但尺度是否为根因尚未做控制变量证明。没有根据GT事后调参，不能概括所有“检测后OCR”组合必然失败。

所有输入使用相同下载原字节并核验SHA256。DP04实际BMP，不按URL后缀猜编码。识别结果三次重复均保留；不存在按结果替换困难图、丢掉空输出或只统计识别成功图片。

## 检测准确率必须分清粒度

参考框是连续对白/旁白段落，45目标中包含一个截断、不可可靠转写的框。严格一对一最大基数匹配，IoU≥0.5：

- **RT-DETR段落框**：TP44、FP0、FN1，precision100.0%、recall97.8%、F1 98.9%。只代表这10张较简单配图和当前手工参考边界。对应的C/D/E复用相同框，不能当作三次独立证据。
- **Paddle DB原始行框**：直接对段落框时TP16、FP74、FN29，F1 23.7%；这是**粒度敏感诊断，不能作为跨模型优劣排名**。一个正确段落可被分成多条正确行框，而每条与大段落IoU不足0.5，主CER仍可很低。IoU0.3时F1变为53.3%，进一步表明阈值与粒度的影响。
- **Tesseract B**没有独立检测器，本轮只取得识别词框，不报告其与段落框的严格检测精度。

本轮没有像素级气泡分割GT、没有真实阅读顺序GT，也没有mAP基准。不要把弱重叠目标计数、文字置信度或框数量称为准确率。

## 参考标注与评分

- 逐图独立视觉转写，未用任何候选输出填答案；45块对白/旁白、44块确定转写。DP03底部截断目标定位但不补字、不进入CER。拟声、道具标签等放入明确忽略区。
- 另一次独立检查复核DP01、DP04、DL03原图与GT，未发现确定需修改之处。仍是助手视觉参考，不等于专业人工双盲评测；边界、标点及非标准阅读顺序可能有误差。
- 主CER先按几何将预测分给参考段落（预测面积至少50%与目标相交），同块按固定坐标顺序拼接，未匹配确定目标计全文漏字，未忽略的额外预测计增字。**这是几何对齐的端到端CER，不是固定GT裁剪下的纯OCR识别率**；跨块合并/顺序错误也会影响它。
- 标准化NFKC后去Unicode空白，保留标点、大小写、数字与繁简差异；辅助列仅再去Unicode P*标点。不做纠错、繁简替换或按模型输出调整答案。
- 完整协议见[annotation-protocol.md](annotation-protocol.md)，评分限制见[scoring-limitations.md](scoring-limitations.md)。21项独立评分单测覆盖空输出、失败分母、S/D/I、最大基数匹配、partial、ignore、uncertain及非法输入。
- GT SHA256：`764cd0ba3b0e2cde475d4df0843821bcdcc16c58c0054ead21a002b6f6bcc891`。全文不公开，因此公开仓库本身不是一个可直接重新评分的完整开放数据集。

## 环境与耗时限制

云 Linux x64、AMD EPYC 9V74，CPU单线程；Tesseract OMP限制1线程，ORT intra/inter-op各1。所有推理持同一文件锁串行运行，排除互相抢CPU；不是Mac M4，不是WebGPU，也不是浏览器端到端。

每图首次+连续两次warm，共3次；只有会话第一图的首次是首次模型推理，不能把后续图的首次叫fresh-process冷启动。没有清OS页缓存。A缓存权重import/init约0.386秒，首图首次0.533秒；Tesseract初始化0.240秒；RT-DETR会话初始化0.479秒。网络下载与安装时间不计入处理时间。

A含每次图片解码、完整OCR调用；B含RGB复制、识别与结果提取。RT-DETR的预处理/检测与识别分批执行，C/D/E表中为阶段耗时相加估计，可能包含重复图片解码，**不能伪称真实集成wall time**。公开逐图测量字段保留在[metrics.json](metrics.json)。两次warm不足以可靠估计p95，不报告p95或统计显著性。

## 许可证、体积与浏览器落地

- RT-DETR模型来源及Apache-2.0声明、11,120,765字节和SHA沿用[预训练检测说明](../../development/pretrained-detector.md)。它已经有浏览器WASM路径；本轮使用Pillow缩放，不与Canvas逐像素等价。
- RapidOCR/PaddleOCR代码Apache-2.0；PP-OCRv5 det/rec官方模型卡声明Apache-2.0。本次ONNX是RapidAI版本化转换制品，不冒称官方原生权重或完成训练数据权利审计。来源/每个权重SHA见公开复现目录模型元数据。
- Tesseract代码及tessdata_best为Apache-2.0；固定提交`e12c65a915945e4c28e237a9b52bc4a8f39a0cec`。仅统计活跃中文权重26.15MB，不等于浏览器峰值内存。
- A约22.04MB活跃模型，D/E再加RT-DETR约11.12MB，C为中文Tesseract约26.15MB再加RT-DETR；运行时及其他依赖另计，未测浏览器峰值内存。
- **A/D/E目前只验证CPU Python/ONNX运行，不代表浏览器WASM/WebGPU、MV3生命周期和首次下载已适配。** B/C中文权重同样尚未替换当前浏览器英语OCR。选择后仍需浏览器适配、离线/首次下载、内存及目标设备测试。

## 怎么选

1. **优先候选A**：这10图质量与速度均领先，建议先做独立浏览器可行性原型，再决定是否替换现有OCR。不是自动切换授权，也没有在本提交切换。
2. **保留RT-DETR作为候选定位能力**：段落定位本身表现好，适合未来气泡筛选/排版边界，但不能直接假定“加在任何OCR前面都更快更准”。
3. **暂不推荐本轮B/C/D/E参数作为默认**：B误检杂字多；C仍有较多识别错误且耗时更高；D多行→单行接口不匹配；E二次检测与默认缩放带来空输出和成本。结论针对这些明确配置，不否定相应项目所有配置。

暂不改产品代码。维护者可以选择A先做浏览器验证，或要求追加具体识别器/分行/裁剪参数的预注册对照后再选。
