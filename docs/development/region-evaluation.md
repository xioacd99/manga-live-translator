# 历史：启发式区域检测与局部 OCR 评估

更新：2026-11-03（Asia/Shanghai）。仅 dev 开发证据，不表示发布或真实漫画验收完成。

> 当前默认区域检测已改为[预训练 RT-DETR](pretrained-detector.md)。下文保留旧 `light-components-v1` 的实现、实验和限制用于历史对照，不代表当前默认检测器、下载策略、资源上限或准确率。旧基准脚本仍评估旧实现。

## 历史实现与边界

`extension/adapters/regions.js` 的 `light-components-v1` 是独立编写、随项目 MIT 许可证提供的亮色连通域启发式，不是训练模型、像素语义分割或漫画专用检测器。没有新增依赖、下载权重或外部数据。仅已有 Tesseract.js 6.0.1、core 6.0.0 与打包英文数据执行 OCR，现有许可证说明仍适用。

- 浏览器从实际图片字节解码，经 canvas 读取 RGBA；纯函数 `detectRegionsFromRgba` 可独立验证。原图上限 16,000,000 像素、字节上限 20 MiB；最长不超过 1,048,576 个采样像素，按面积等比缩小。
- 亮色条件为 alpha ≥240 且 RGB 各通道 ≥220；`lightThreshold` 可配置为 160–250 的整数，其余参数属于固定检测版本。四邻域连通，不接触采样图边缘，框宽至少 16、高至少 12、面积至少 256 且至多占图像 80%，亮色填充至少占框 50%。内缩短边 15%（至少 2 像素）后暗点比例必须处于 0.005–0.45。
- 返回框向外取整映射到原图；候选至多 32 个，超额整图回退。`confidence: 0.6` 是固定启发式接受分数，不是训练所得概率或校准过的文字置信度。
- 按 y、再 x 排序，仅适用于当前英文预览的简单从上到下、从左到右顺序。不是跨面板阅读顺序模型；日文竖排、右到左、多列不等高和复杂分镜尚未验收。
- `config.regionMode` 默认 `conservative`：先局部 OCR，再执行整图 OCR 补漏；`whole-image` 显式只做整图；`regions-only` 仅供实验比较，不是用户默认。无候选、低检测置信度、异常/超额几何和空/低置信度 OCR 都回到整图。实验模式仍可能漏掉气泡外文本，不能作为已验证的安全默认。
- OCR 矩形总面积至多为原图的两倍，框数至多 32；候选段落与最终段落另有数量上限。相同坐标且相同/包含文字会去重，高置信度整图段落覆盖的低置信度冲突候选不重复显示。其他位置的相同对白保留。默认不会因“不是气泡”跳过整图识别，但整图 OCR 本身仍可能漏字。
- 检测配置、版本、实际返回区域、OCR 配置及裁剪修订都须进入缓存身份。改变阈值或区域不能复用旧局部 OCR；纠错和上下文变化不应重新执行检测。

## 可重复运行

```sh
node --test tests/js/regions.test.js tests/js/regions-ocr.test.js tests/js/adapters.test.js tests/js/adapters-ocr-smoke.test.js
node benchmarks/regions.mjs
```

基准输出 JSON 包含每项框、真阳性/误检/漏检、计时以及实际 OCR API 调用。样本在脚本中独立绘制：320×240 RGBA 几何框和暗条，没有用户漫画、外部字体或图片。真实 OCR 字形由已有 `tests/fixtures/generated-english.js` 独立绘制。

框评估采用一对一贪心 IoU≥0.5 匹配。标注框为白色内部；无边框样本标注其暗条文本框，断裂框仍标注其原先内部，非文字图案故意标注为空，暴露启发式无法判别语义的弱点。precision 分母为检测数，recall 分母为标注数；零分母记为 null，不将空白页算成 100%。这套人为构造样本用于回归，不具有总体代表性。

## 本次实测

云端 Linux/x64，Node v24.22.1，每样本 25 次（含首次运行，无单独预热），2026-11-03。不同进程负载、JIT 和运行时可能改变计时。

| 合成样本 | 标注/检出 | TP/FP/FN | precision/recall | 匹配平均 IoU | 检测 p50/p95 ms |
| --- | --- | --- | --- | --- | --- |
| 封闭矩形气泡 | 2/2 | 2/0/0 | 1/1 | 1 | 1.880/13.174 |
| 旁白框 | 1/1 | 1/0/0 | 1/1 | 1 | 1.774/2.000 |
| 无边框对白 | 1/0 | 0/0/1 | null/0 | null | 1.887/6.151 |
| 无文字白页 | 0/0 | 0/0/0 | null/null | null | 1.986/2.825 |
| 断裂异常边框 | 1/0 | 0/0/1 | null/0 | null | 2.065/2.477 |
| 多列气泡 | 4/4 | 4/0/0 | 1/1 | 1 | 1.910/2.455 |
| 框内图案非文字 | 0/1 | 0/1/0 | 0/null | null | 2.008/2.630 |

合计 TP=7、FP=1、FN=2，precision=0.875、recall≈0.778。数字只描述上述七个自制几何样本，不能称为漫画检测准确率。无边框和断裂边框会漏检，框内图案会误检；缩小采样还可能抹去细边框或微小文字。因此保留默认整图补漏，不宣称局部方式更快或更准。

## 真实打包 OCR 的同图对照

对 800×160 合成 `HELLO WORLD` 位图执行真实离线 Tesseract，不使用 mock OCR 或付费服务：

1. 整图输出 `HELLO WORLD`，置信度 71，bbox `(50,40)–(700,110)`。
2. 以 rectangle `{left:390,top:20,width:330,height:110}` 识别右侧文字，输出错误的 `LORELD`，置信度 0，bbox `(410,40)–(700,110)`。
3. 低置信度触发整图回退，最终保留 `HELLO WORLD`；冲突的低置信度框不重复显示。

真实返回证明 **Tesseract rectangle 的 bbox 已在原图坐标系**，不能再次加上 rectangle 的 left/top。该实验同时证明裁剪可以降低此合成字体的识别质量。测试断言坐标、实际调用及回退，不能把正确映射当作局部识别质量通过。

本次调用级耗时依次为 221.859、132.592、145.271 ms；首个整图包含创建 worker 的端到端耗时 488.459 ms，后续暖局部加回退为 278.571 ms。两者冷暖条件不同，且为单次样本，**不能计算或宣称速度提升**。默认保守模式可能增加计算，本实验没有测量用户首次可读时间或真实漫画的收益。

## 内存与取消

采样上限下，纯检测分配 light 1 MiB、Int32 队列 4 MiB，RGBA 输入 4 MiB，总计已知像素缓冲 9 MiB，另有最多 32 个返回框。浏览器还持有原图 bitmap（最大按 RGBA 约 61 MiB）、采样 canvas（至多 4 MiB），解码器、JS/浏览器开销及 OCR WASM 内存另计；**这些是代码缓冲大小上限计算，不是进程峰值内存实测**，不能声称已验证设备安全内存预算。

位图在成功、失败及取消路径均关闭；像素循环和 OCR 每次异步操作前后检查取消。纯像素循环是有界同步工作，事件循环新收到的取消无法中断当前同步循环，要等循环返回；不能称为即时抢占。OCR 取消等待共享 worker 清理，取消后不继续启动下一裁剪或整图补漏。
