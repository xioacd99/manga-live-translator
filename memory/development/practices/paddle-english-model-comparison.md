# Paddle英文型号比较经验

- 状态：resolved（本轮评测完成，产品方案待选择）。日期：2026-11-03，Asia/Shanghai。
- 来源：[图文报告](../../../docs/evaluation/paddle-english-models-2026-11-03/README.md)、[方法](../../../docs/evaluation/paddle-english-models-2026-11-03/METHODS.md)。
- 原英文输入和冻结GT均按SHA完整恢复后复用。共享执行目录不能作为唯一备份；公开仓库只留许可合适的图表和非全文证据，原图/GT/预测在私有评测备份中保留。
- RapidOCR版本升级与模型变化须分离：同v5权重在3.4.5和3.10.0的框/文字/识别分数一致，CER精确复现；耗时仪器和环境变化时必须全组重跑。
- RapidAI有意选定的检测归一化/DB参数与百度官方不同，不是单凭模型名字就能代表官方流水线。预先指定small同权重参数对照，结果指标各有改善和退步，不能只挑最好一个分数。
- 捕获原始DB分数时发现框排序可能未同步分数；禁止用该字段解释单框质量。无几何匹配输出、字符删除、整页漏检是不同概念。
- 本轮small更适合作为下一步浏览器候选，medium更准确但云CPU更慢且权重更大；这些不是M4/浏览器测量，也不是翻译质量结论。未修改默认模型、合并main或发布。

## 质量优先、分辨率和生成式OCR（2026-11-03）

- [后续图文实测](../../../docs/evaluation/paddle-accuracy-resolution-2026-11-03/README.md)：固定small参数组短边1024/1536/2048/2560、长边4096上限，同10图每档3遍。2048→2560只少4次字符编辑，删除数不变、WER变差，同时耗时与RSS增加；不能用更大分辨率直接保证更高质量。实际检测tensor shape必须记录，cap可能使不同档相同。
- 官方VL1.6 GGUF在本机CPU能跑Spotting，但真实10图有两页重复循环直至输出上限；合成两行通过不能替代真实页稳定性验证。无已确认根因，保留固定协议、原始输出和失败分母，禁止加预算/删重复后冒称原实验成功。
- 字符删除包含格式/预算失败引起的整页拒绝，不等于模型纯识字上限。生成式最终区域与DB独立检测行框粒度不同；评分投影只删除空detectorRegions键，不能把无独立阶段当零召回。
- 故障后提出的离线回退严格只按error整页选择固定旧small预测，不按GT选字。它是探索性诊断，不是最初预注册或已集成混合系统，也没有同资源混合时延。成功8页对照是事后子集，必须同时给完整10页结果。
- CPU4单遍VL请求不含事先PIL预处理；CPU1传统OCR含图像预处理且报告重复暖调用。不得直接计算两者的速度倍率或推断Mac M4。公开仓库仅保存非全文指标、图表和复现代码；模型、漫画原图与完整预测/GT不公开。
