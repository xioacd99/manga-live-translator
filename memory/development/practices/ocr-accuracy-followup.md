# 英文OCR追加精度验证经验

状态：resolved（本轮研究与实测完成，不代表产品模型选择完成）。日期：2026-11-03，Asia/Shanghai。

## 观察与结论

固定扩边并不总能减少裁字：同10图的A方案CER17.65%，比medium1536基线13.45%更差。三视图按同识别器置信度选字得到13.14%，只少7编辑错误、耗时约2.34倍，不能把小样本改进宣称普遍提升。docTR DB-R50＋PARSeq官方1024词级管线CER36.70%，官方通用文档能力并未在本历史漫画集胜出。

## 可复用做法

- 不依赖GT选分支；B原视图逐图框/文字/分数与旧基线完全一致后，才将其作为可靠桥接。没有另称新跑独立基线。
- 诊断字符串长度必须标明原始len或评分NFKC去空白。两种统计不同不能误判实现冲突；变短行更多也不证明总字符变短或准确性因果。
- NumPy bool等诊断字段在整页计算后才JSON失败会浪费运行。合成测试应覆盖完整序列化，不仅模型输出。此轮仅修序列化重新冻结整组重跑，保留失败证据。
- 包metadata版本和模块__version__可能带v前缀；精确核两种预期而不是盲目放松校验。修复加载前断言不属于识别失败或调参。
- 词级docTR与行级Paddle不能用段落GT的严格IoU直接比较检测能力；采用相同几何归属和文本评分，并报告粒度与resize差异。
- 宽松代码许可不自动覆盖所有模型。漫画专用checkpoint、非商业条款、竞争使用和输出义务需单独核；未测LightOnOCR-3不列精度排行榜。
