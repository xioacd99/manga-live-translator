# 浏览器拥有的本机 OCR 生命周期

- 状态：实现和本机测试完成，实际 Chromium 结果以对应提交 CI 为准。
- 更新日期：2026-11-04，Asia/Shanghai。
- 范围：Chrome MV3、Python Native Messaging 宿主、自动管理与手动服务隔离。
- 背景：扩展沙箱不能直接执行 Python。仅启动一个独立 HTTP 子进程而不约束所有权，会在浏览器退出后遗留模型进程；按固定端口/PID 扫描终止又可能关闭其他浏览器或用户服务。
- 决策：显式安装精确扩展白名单宿主，使用 Native Messaging 长连接承载同一进程内 HTTP 线程。每连接随机令牌、系统分配环回端口；只关闭自己的连接和进程，不触及手动服务。
- 实践：状态查询、浏览器启动不创建宿主；用户启用/下载动作才启动。非秘密自动管理偏好可持久化，但端口、令牌与远端密钥不持久保存。关闭最后普通窗口主动断线，管道 EOF 为独立退出路径。
- 已复现的竞态：模拟延迟返回的空 windows.getAll 快照会误停新窗口刚启动的宿主。窗口创建/移除代次让旧查询失效，新增回归验证旧空/非空快照不能覆盖当前窗口状态；这是确定的 API 排序测试，不是声称已在真实浏览器复现。
- 安全边界：宿主只接收严格有界 start/stop 消息，无任意命令、路径、URL；协议输出与第三方库日志隔离。模型仍显式下载，完整文件原子替换；异常终止可能留下未完成临时文件，不能将其当权重。
- 验证：测试覆盖范围和最终结果见[生命周期文档](../../../docs/development/native-lifecycle.md)及对应开发提交 CI。不能将真实管道/HTTP启动测试当作模型推理、Mac/M4或真实漫画站点验收。
- 限制：不同浏览器连接分别加载模型，内存可能重复；安装器为 macOS/Linux，Windows保留手动模式。首次用户安装与权限同意不可由扩展静默完成。
- 参考：[Chrome 官方 Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)、[服务指南](../../../services/local-ocr/README.md)。
